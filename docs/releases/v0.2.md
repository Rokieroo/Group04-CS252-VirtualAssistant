# Pathly v0.2: the core loop, syllabus → roadmap → resources

First tagged release (`v0.2`). It covers the work merged since the spec 3.0 refocus
(#47) up to the cost dashboard (#69). Numbers are issues or pull requests.

## Highlights

- **Syllabus in, roadmap out.** Upload a syllabus as PDF, DOCX or pasted text (#49, #74).
  The syllabus and roadmap API is #63. Topics are normalised (#50, #73) and built into a
  roadmap of weekly steps with prerequisite edges and exam milestones (#60, #85).
- **A plan that respects the roadmap.** The planner schedules steps by dependency,
  release date and weekly load, and reports overloaded weeks (#52, #80).
- **Resources that are verified, scored and curated.** Search providers (internal
  catalog, YouTube, web) with PII-free queries (#61, #84). A safe fetcher with an SSRF
  guard, a domain policy and paywall rules (#64, #86). A vetting judge whose
  `evidence_quote` must appear verbatim in the page, plus a 7-criterion score, MMR curation and
  "not helpful" replacement (#62, #87).
- **Background work.** A database job queue and worker. The search cache is shared for 7
  days per node signature, and shown links are checked daily (#68, #81).
- **Cost and quota dashboard.** Every resource search logs its queries, candidates,
  kept sources, LLM and search cost and per-provider latency. Admins see the cost per
  roadmap step at `#costs` (#69).
- **Code layout.** Logic lives in `src/app/<part>` and HTTP in `src/assistant/backend` (ADR 003, #72).
  Shared prompt blocks and API error parsing (#77, #78), and core-loop navigation in the UI
  (#53, #79).

## Upgrade notes

- **Database:** pending migrations, up to `0007_search_metrics`, run when the API starts.
  `0007` adds `resource_searches` and the `latency_ms`, `cost_usd` and `search_id`
  columns on `search_runs`. Start the API before the worker.
- **Worker:** redeploy the Render/Compose `worker` service. It now also runs
  `search_resources` jobs.
- **New dependency:** `trafilatura` (readable page text for vetting).
- **Admins:** promote an operator with
  `UPDATE users SET role = 'admin' WHERE email = '...'` (see `docs/DEPLOYMENT.md`, Step 5).
- **Environment:** `YOUTUBE_API_KEY` and `SEARCH_API_KEY` are optional. Without them,
  search falls back to the internal catalog.

## Staging demo script

1. Register, create a course, upload its syllabus and review the learning outcomes.
2. Generate the roadmap and schedule it for a weekly budget.
3. Enqueue `search_resources` for a step. Until the resources API from #65 lands, use
   `jobs.enqueue(db, "search_resources", {"node_id": ...}, now=..., user_id=...)`.
   The worker links the verified sources to the step.
4. Sign in as an admin and open `#costs`: the step's cost, cache hits and provider
   latency are listed. Searching the same step again is served from the cache at no cost.
